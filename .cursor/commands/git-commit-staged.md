# git-commit-staged

**ステージ済み（`git add` 済み）の変更だけをコミットする。** 未ステージの変更は追加しない。コミットメッセージは **日本語**（`.cursorrules` / `generate-commit-messages` 規約）。

## 前提

- ワークスペースが **Git リポジトリ**であること。
- ユーザーが本コマンドを実行した時点で、コミット作成の依頼とみなす。
- **`git add` で新たにステージしない**（既に index にあるものだけを対象）。

## 実行してほしいこと

1. **並列で状態を確認**（Shell）:
   - `git status`
   - `git diff --cached`（ステージ済み差分。要約用）
   - `git log -8 --oneline`（メッセージ文体の参考）

2. **ガード**:
   - ステージ済み変更が **無い**場合はコミットせず、その旨を報告して終了する。
   - `.env` / 認証情報など **シークレットらしきファイル**がステージに含まれる場合はコミットせず警告する。
   - `git config` の変更、`--no-verify`、force push、`amend`（ユーザー明示依頼がない限り）は行わない。

3. **コミットメッセージを起草**:
   - **日本語**・1〜2 文。**なぜ**を優先し、変更の性質（追加 / 修正 / リファクタ 等）が分かるようにする。
   - 例: 「〇〇機能を追加」「〇〇のバグを修正」「〇〇をリファクタ」

4. **コミット実行**（PowerShell ではヒアドキュメント相当でメッセージを渡す）:

   ```powershell
   git commit -m @"
   <コミットメッセージ>

   "@
   ```

   bash 利用時の例:

   ```bash
   git commit -m "$(cat <<'EOF'
   <コミットメッセージ>

   EOF
   )"
   ```

5. **事後確認**: `git status` を実行し、コミットハッシュ（または短ハッシュ）・メッセージ・作業ツリー状態を短く報告する。
6. **フック失敗時**: amend せず、原因を直したうえで **新しいコミット**を作る（ユーザーが明示した場合を除く）。

## やらないこと

- 未追跡・未ステージファイルの `git add`
- リモートへの `push`（別途依頼がある場合のみ）
- ブランチの切り替え・作成（本コマンドの範囲外）

## ユーザー向け短文（チャットへの貼り付け用）

ステージ済みの変更だけを、日本語のコミットメッセージでコミットしてください。未ステージのファイルは追加しないでください。
