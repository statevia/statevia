# git-pr-create

**現在ブランチから GitHub Pull Request を作成する。** GitHub 操作は **`gh`** を使う。タイトル・本文は **日本語**（リポジトリのコミット／PR 慣習に合わせる）。

## 前提

- ワークスペースが **Git リポジトリ**であること。
- **`gh`** が認証済みであること（`gh auth status` で確認可能）。
- ユーザーが本コマンドを実行した時点で、**PR 作成の依頼**とみなす。
- ベースブランチの既定は **`main`**（ユーザー指定があればそれを優先）。

## 実行してほしいこと

1. **並列で状態を確認**（Shell。TodoWrite / Task ツールは使わない）:
   - `git status`（未追跡・未コミットの有無）
   - `git diff` および必要なら `git diff --cached`（未コミット差分の把握）
   - 現在ブランチの upstream 有無・追従状況（例: `git status -sb` / `git rev-parse --abbrev-ref @{upstream}`）
   - `git log` と `git diff <base>...HEAD`（**base から分岐して以降の全コミット**と差分。最新コミットだけ見ない）

2. **ガード**:
   - **未コミットの変更**がある場合は、内容を短く示し、コミット／stash するか確認してから進む（勝手にコミットしない。コミットが必要なら `/git-commit-staged` 等を案内）。
   - 現在ブランチが **`main` / `master`** のときは PR を作らず、作業ブランチへの切り替えまたは作成を案内する。
   - `git config` の変更、`--no-verify`、**force push**（ユーザー明示がない限り）は行わない。
   - **main/master への force push は禁止**し、依頼されても警告する。

3. **PR テンプレート**:
   - `.github/PULL_REQUEST_TEMPLATE.md` や `.github/PULL_REQUEST_TEMPLATE/` があれば内容を読み、本文構成に反映する。
   - 無い場合は下記の Summary / マージ方式 / Test plan 形式を使う。

4. **要約の起草**:
   - **base...HEAD に含まれる全コミット**を踏まえ、タイトル（簡潔・日本語）と本文を書く。
   - 本文は変更の **目的・範囲** が分かる 1〜3 箇条と、検証チェックリストを含める。
   - 本文に **マージ方式の推奨** と理由（1 行）を含める。各コミットのメッセージと差分を見て次の基準で判定する（PR 作成時点の推奨であり、最終判断はマージ時にレビュアーが行う）:

     | 推奨 | 判定基準 |
     | --- | --- |
     | 通常マージ | 各コミットが論理単位（層・画面・リファクタ等）で分かれ、単独でビルド・テストが通り、メッセージで内容が分かる |
     | スカッシュマージ | 「WIP」「レビュー指摘を反映」「typo 修正」等の途中コミットが中心、または変更全体が 1 つの小さな論理変更 |
     | 整理してから通常マージ | 論理単位で分かれているが途中コミットが少数混在する（対象コミットを挙げ、fixup での整理を促す） |

5. **リモートへ push**（未 push または upstream 未設定のとき）:

   ```powershell
   git push -u origin HEAD
   ```

   既に upstream があり最新なら、不要な push は省略してよい。

6. **PR 作成**（`gh pr create`。本文はヒアドキュメント相当で渡す）:

   PowerShell 例:

   ```powershell
   gh pr create --title "<日本語タイトル>" --body @"
   ## Summary
   - <箇条書き 1〜3>

   ## マージ方式
   - 推奨: <通常マージ / スカッシュマージ / 整理してから通常マージ>
   - 理由: <1 行>

   ## Test plan
   - [ ] <検証項目>
   - [ ] <検証項目>

   "@
   ```

   bash 例:

   ```bash
   gh pr create --title "<日本語タイトル>" --body "$(cat <<'EOF'
   ## Summary
   - <箇条書き 1〜3>

   ## マージ方式
   - 推奨: <通常マージ / スカッシュマージ / 整理してから通常マージ>
   - 理由: <1 行>

   ## Test plan
   - [ ] <検証項目>
   - [ ] <検証項目>

   EOF
   )"
   ```

   - ベースがテンプレートにある場合は、その見出し・必須項目を優先する。
   - `--base` が必要なときだけ明示（既定 `main` 以外をユーザーが指定したとき）。

7. **結果**: 作成された **PR URL** を必ず報告する。失敗時はエラー内容と次の一手を書く。

## やらないこと

- コミットの新規作成（本コマンドの範囲外。必要なら `/git-commit-staged`）
- ブランチの切り替え・強制リセット
- レビュー依頼の一括アサインなど、ユーザーが求めていない `gh` 操作の拡大

## ユーザー向け短文（チャットへの貼り付け用）

現在ブランチの変更を push し、`gh pr create` で日本語タイトル・本文の Pull Request を作成してください。base...HEAD の全コミットを踏まえ、最後に PR URL を報告してください。
