---

**Statevia Studio**（`nodejs/studio/`）は Next.js の Web ダッシュボードです。Service API へはブラウザから直接呼ばず、**同一オリジンのプロキシ**（`/api/core/*`）経由でアクセスします。

## 起動

Service API と PostgreSQL が起動している状態で:

```bash
cd nodejs/studio
SERVICE_API_INTERNAL_BASE="http://localhost:8080" npm run dev
```

ブラウザで `http://localhost:3000` を開きます。Docker Compose 利用時は [operations-docker.md](operations-docker.md) を参照。

## サインイン

`/login` からテナントキー・ユーザー名・パスワードでサインインします。初回管理者の作成は [operations-tenant-bootstrap.md](operations-tenant-bootstrap.md)。環境変数とテナント設定は [ui-auth-tenant-config.md](ui-auth-tenant-config.md)。

ログイン後はヘッダー右端のユーザーメニューの「ログアウト」で Studio のセッション Cookie を消し、`/login` へ戻ります（ログイン画面では出しません）。Service API の JWT をサーバー側で即時失効はしません。ブラウザからセッションが無くなれば Studio は再ログインが必要です。

パスワードを忘れた場合のメール再設定は提供しません。管理者がユーザー管理から上書きするか、本人が `/account` で現行パスワードを確認して更新します。更新後も既存セッション（JWT）は期限まで有効です。

## 画面の移動

ログイン後は左のサイドメニューから画面を開きます（ログイン画面では出しません）。項目はグループに分かれ、権限が無いグループは見出しごと出ません。今いる画面の項目は強調されます。

| グループ | 項目 | 表示される利用者 |
| --- | --- | --- |
| （先頭） | プロジェクト切替 | 所属 Project がある利用者 |
| ワークフロー | ダッシュボード、定義、実行 | 全員 |
| プロジェクト | メンバー | 選択中 Project の project.admin |
| プロジェクト | プロジェクトを作成 | グループ権限 `projects.create` を持つ利用者（所属が無くても出る） |
| テナント管理：アクセス | ユーザー管理、グループ管理、API キー | tenant.admin |
| テナント管理：連携・設定 | プロジェクト、Action バインディング、通知 SMTP | tenant.admin |

| 操作 | 方法 | 備考 |
| --- | --- | --- |
| グループの開閉 | グループ見出しを押す | 開閉はブラウザに残る。今いる画面のグループは開いた状態で表示されるが、見出しで閉じられる |
| メニューを畳む | メニュー下端のボタン | アイコンだけの細い列になる。状態は Cookie（`ui-sidenav`）に残る。畳んだままプロジェクトのアイコンを押すと広がる |
| 狭い画面 | ヘッダー左端のメニューボタン | メニューが重なって開く。項目を選ぶか、外側か Escape で閉じる |
| アカウント・ログアウト | ヘッダー右端のユーザーメニュー | ログイン画面では出さない |

メニューに出ないことは権限の判定ではありません。管理画面の URL を直接開いても、tenant.admin でなければダッシュボードへ戻ります。

| 画面 | 目的 |

| アカウント (`/account`) | 現行パスワード確認付きで自分のパスワードを更新 |

| プロジェクト作成 (`/projects/new`) | Project の作成。`projects.create` |
| 管理プロジェクト (`/admin/projects`) | テナント内の全 Project とメンバー。tenant.admin。`projects.create` があれば作成画面へのボタンが出る。定義エディタは開かない |
| 実行詳細 / グラフ | 状態・エッジ・進行の可視化 |

### パスワード更新

| 操作 | 画面 | 備考 |
| --- | --- | --- |
| 本人更新 | ユーザーメニュー「アカウント」→ `/account` | 現行・新規・確認。確認不一致では送信しない。管理者以外も利用可。新規は 8〜128 文字・空白なし（記号可） |
| 管理者更新 | ユーザー管理の各行 | ダイアログで新規と確認。現行パスワードは不要。新規は 8〜128 文字・空白なし（記号可） |

### 所属 Project

ログイン後のサイドメニュー先頭で、自分が所属する Project を選びます。ダッシュボードの直近実行、定義一覧、定義の作成、実行一覧は、その Project に従います。所属が無い定義の詳細は開きません。

| 操作 | 画面 | 備考 |
| --- | --- | --- |
| 切替 | サイドメニュー先頭のプロジェクト | 所属だけが出る。選択はブラウザのセッションに残る |
| メンバー | サイドメニュー「プロジェクト」→「メンバー」、または `/projects/members` | project.admin。ユーザー名と API キー名で付与する。UUID は入力しない |
| 作成 | サイドメニュー「プロジェクト」→「プロジェクトを作成」（`/projects/new`）。`/admin/projects` の「プロジェクトを作成」ボタンからも同じ画面へ進む | グループ権限 `projects.create`（tenant.admin は常に持つ）。所属が無くても作れる。権限が無いときはフォームを出さない |
| 全 Project | `/admin/projects` | tenant.admin。未所属でもメンバーは付けられる。定義の編集画面へは進まない |

作成の項目は次のとおりです。前後の空白は除きます。

| 項目 | 必須 | 制約 |
| --- | --- | --- |
| プロジェクトキー | 必須 | 1〜128 文字。テナント内で一意。既にあればプロジェクトキー欄にエラーを出す。API・CLI から Project を指す名前（HTTP の項目名は `slug`）。画面には表示名が出る |
| 表示名 | 必須 | 1〜256 文字 |
| 説明 | 任意 | 空白だけなら送らない |

作成した人はその Project の管理ロールになり、作成後はその Project が選ばれます。作成のあと所属の取得に失敗したときは、作成済みである旨を出すので、ページを再読み込みしてください。同じ内容で作り直すとプロジェクトキーの重複になります。

ロールは閲覧、実行、公開、管理の順に強い。定義の作成には公開以上が必要です。Project 自体を削除する操作と、作成後に名前やプロジェクトキーを変える画面は無い。

Project ロールに加えて、所属グループの権限も要ります。

| 操作 | Project ロール | グループ権限 |
| --- | --- | --- |
| 定義の作成・編集・削除・復元 | 公開以上 | `definitions.write` |
| 実行の開始 | 実行以上 | `executions.write` |
| 実行の取消・Resume・イベント送信 | 実行以上 | `executions.write` |

足りない操作のボタンは出ません。エディタ、実行開始画面、Run 画面は理由を表示します。グループ権限はテナント管理者が管理画面の「グループ」で付けます。

実行の取消・Resume・イベント送信では、Studio はグループ権限だけを見ます。実行の応答に Project が含まれないため、Project ロールは Service API が判定し、足りなければ 403 になります。

HTTP 契約の正本は [api-http.md](../specifications/api-http.md) §2.7。

### 定義 catalog の論理削除・復元

Studio の定義一覧・詳細から Service API の catalog ライフサイクルを操作できる。

| 操作 | 画面 | 備考 |
| --- | --- | --- |
| 論理削除 | 一覧（active 行）・詳細 | インライン二段階確認のあと `DELETE /v1/definitions/{id}` |
| 削除済みを含む一覧 | 一覧の「削除済みを含む」 | URL `includeDeleted=true`。行に `deletedAt` と削除バッジ |
| 復元 | 一覧の削除済み行のみ | 単体 GET は 404（operational invisibility）のため詳細からは復元しない |

HTTP 契約の正本は [api-http.md](../specifications/api-http.md) §2.1.2–2.2。

### 定義エディタの YAML ファイル入出力

定義の新規作成と更新の画面で、「アップロード」と「ダウンロード」を使えます。YAML / Graph の切替は左、この2つは右です。アップロードは画面上の YAML を差し替えるだけで、Service API へは送りません。登録は従来の「保存」です。

| 操作 | 結果 |
| --- | --- |
| アップロード | `.yaml` / `.yml`。UTF-8。先頭の BOM は除く。256KB（262144 バイト）を超えるファイルは読み込まない |
| 未保存の上書き | 編集中の内容があるときは、確認のあとだけ差し替える。キャンセルすると内容は残る |
| ダウンロード | YAML 表示中は画面のテキスト。Graph 表示中は保存時と同じ YAML。定義名が空なら `definition.yaml` |

### 実行詳細の循環と一覧

同じ状態に実行が複数あるとき、グラフ上のマスは 1 つのままです。色は待機中の訪問を優先します。ノード詳細では、見出しの右にある移動で、1 つ新しい訪問、1 つ古い訪問、いちばん新しい訪問、いちばん古い訪問へ移れます。この移動は訪問が 2 件以上のときだけ出ます。ノード一覧は状態ごとに 1 行で、左の印を開くと `状態名 (試行回数)` の行になります。状態が 21 件以上のときは、見出し右のページ移動で 20 件ずつ見ます。再開はそのとき詳細に出ている訪問に対して行います。選択していた訪問が無くなったときは、同じ状態が残っていればいちばん新しい訪問へ移ります。

グラフのマージ規則・ノード表現の Normative 契約は [visual 仕様](../specifications/ui/visual.md)。実行グラフ上の代表と詳細の訪問の対応は [execution-graph 仕様](../specifications/execution/execution-graph.md) を参照します。リアルタイム更新は SSE（[push-api 仕様](../specifications/ui/push-api.md)）。SSE も Principal 必須（未認証は 401）。Studio はプロキシ経由でセッション Cookie を付ける。

## コントリビュータ向け

Studio の内部モジュール境界（薄い `app/` + `features/` + `shared/`）は [ui-studio-structure.md](../architecture/ui-studio-structure.md) を正本とする。画面追加や import 規約はそちらを参照する（本ガイドの利用者向け操作・HTTP 契約は変えない）。

```bash
npm run lint
npm run typecheck
npm run test:run
```
